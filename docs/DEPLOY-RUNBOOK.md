# AgriSphere — Deployment Runbook (production-ready)

> Written 2026-09-07 against commit `aca5e4a` + the production-readiness
> release. Purpose: an operator (the owner) can take this repository from
> GitHub to a live, durable, honest production deployment in about an hour.
> Everything marked **[operator]** is a human/business step that no code can
> do for you — treat it as part of the definition of done.

## 1. What "production-ready" means here (and what it does not)

**Ready (verified in this release):**
- Durable state: `render.yaml` mounts a persistent disk; `DATA_DIR` points at
  it; JSON/SQLite collections, uploads and backups all live on the disk
  (AUDIT O1 resolved — free tier was the blocker and is no longer the plan).
- Every restart keeps data; automatic snapshot every 6 h + on-demand admin
  backup download for off-site copies (AUDIT O2/O3 resolved).
- Account data dignity: `GET /api/me/export` + `DELETE /api/me` (AUDIT E-gap
  resolved); photo files are removed from disk on erasure.
- Security headers (nosniff, frame-options, referrer-policy, permissions
  policy, COOP, HSTS behind HTTPS); admin token header-only + timing-safe;
  in production the admin surface refuses to open without `ADMIN_TOKEN`, and
  webhook verification refuses to open without `VERIFY_TOKEN`.
- Rate limits on OTP issue/verify, alert subscriptions, photos, reports,
  geo-trace lots, chat; per-channel opt-outs honoured end-to-end.
- CI runs the full smoke suite (164 assertions) on Node 20 and 22.
- New flagship wedge: geo-trace holdings (consent-first, owner-controlled
  sharing) + consignment lots + self-declared **EUDR-readiness export**
  (CSV/JSON) for the 30 Dec 2026 / 30 Jun 2027 timeline.
- Public `/trust` page with live computed facts — no marketing numbers.

**Not ready / intentionally out of scope (do not claim otherwise):**
- **Entity & contracts** [operator]: registered legal entity, bank account,
  DPA, and professional review of the `docs/templates/` documents are
  pre-launch business steps outside the codebase.
- **Channel credentials** [operator]: WhatsApp/Messenger/Telegram tokens are
  dashboard secrets; until set, `healthz` shows `channels: false` and the
  chat works on Web/USSD only. That is displayed honestly everywhere.
- **External security review**: no third-party pentest/fuzz has been run.
  The smoke suite is regression coverage, not a security audit.
- **Scaling**: rate limiter and store are single-instance by design. Beyond
  one instance, move the limiter to a shared store and pick a shared DB.
- **EUDR**: the geo-trace export is self-declared documentation support —
  not a certificate and not a TRACES due-diligence statement. Legality and
  deforestation-risk assessment remain the operator's duty. Botswana's
  practical burden depends on EC implementing acts — re-check quarterly.

| # | Check | How |
|---|---|---|
| 1 | `node --check` passes everywhere | CI does it |
| 2 | Smoke suite green | `npm test` (CI does it) |
| 3 | No uncommitted secrets | `git status` clean; grep for tokens in envVars |

## 3. Deploy (Render)

1. Push to GitHub `main` (or merge PR #1). `render.yaml` `autoDeploy: true`
   builds the web service; **do not create it with the old free plan** — if a
   free service already exists, delete it first, then let the blueprint
   create the paid one with the disk.
2. Dashboard → your service → **Disks**: confirm `agrisphere-data` at
   `/var/data`, 1 GB.
3. **Secrets** (Dashboard → Environment, never commit):
   - `VERIFY_TOKEN` — already auto-generated by the blueprint; keep it.
   - `ADMIN_TOKEN` — auto-generated; copy it to your password manager.
   - Optional: `TEACH_TOKEN`, `WHATSAPP_TOKEN`+`WHATSAPP_PHONE_ID`,
     `FACEBOOK_PAGE_TOKEN`, `TELEGRAM_TOKEN`, `SMS_PROVIDER_URL`/`KEY`,
     `OPENAI_API_KEY` (stays off unless deliberately enabled).
4. Trigger deploy. Wait for the health check to pass (`/healthz` → 200).
5. **Post-deploy verification (below) must pass before you call it live.**

## 4. Post-deploy verification

```bash
BASE=https://<your-service>.onrender.com

# 1. Health — status ok, engine "local", channels reflect your secrets,
#    counters sensible, backend json|sqlite
curl -s $BASE/healthz

# 2. Trust page renders and lists live facts (no placeholders)
curl -s $BASE/trust | head -20

# 3. Admin protected: without token → 403; with header → 200
curl -s -o /dev/null -w '%{http_code}\n' $BASE/api/admin/learned
curl -s -H "x-admin-token: $ADMIN_TOKEN" -o /dev/null -w '%{http_code}\n' $BASE/api/admin/learned

# 4. Backup endpoint returns a full snapshot; download a copy off-site now
curl -s -H "x-admin-token: $ADMIN_TOKEN" $BASE/api/admin/backup > backup-$(date +%F).json

# 5. Geo-trace round trip (W1): create a consent holding, consignment, lot,
#    export CSV — see the smoke suite §30 for the exact payloads.

# 6. DURABILITY TEST (the old killer): chat once, note the session message
#    count, trigger "Deploy latest commit" from the dashboard (or restart),
#    then chat again — history, learned entries and stats must survive.
#    If state is lost, the disk is not mounted — stop and fix before launch.
```

## 5. Backups & disaster recovery

- **In-app**: automatic snapshot to `/var/data/backups` every 6 h, newest 10
  kept. Writes are atomic (tmp+rename) per collection.
- **Off-site (weekly minimum)**: download `GET /api/admin/backup` (command
  in §4.4) into your own storage (e.g. a private bucket/drive). A Render
  disk is not off-site.
- **Restore drill**: stop service → copy a backup JSON over the collection
  files in `/var/data` → start service → verify counts in `/healthz`.
  Practice once before launch and note the date in the governance log.

## 6. First-load data (before announcing)

1. **Official price references** (admin, `/api/prices/references`): load the
   current BAMB depot bulletins only — with source + date + URL. Prices are
   the trust wedge; never seed invented numbers.
2. **Seeded programmes**: one or two genuine buyer-led programmes with full
   fair-terms fields (use the OFFTake MOU template) so the marketplace is
   not empty on day one.
3. **Extension & vet contacts**: the knowledge base references them; keep a
   short list with the exact routes to update in the KB.
4. **First geo-trace pilot partner**: one export-facing conversation
   (BMC/MIRA ecosystem, export abattoir, EU buyer) per STRATEGY §9 Day 1–30.

## 7. Launch order (honest, staged)

1. Quiet launch to **pilot farmers + 3 LOI partners** (Web + USSD; WhatsApp
   test-number demo if the token is set) — STRATEGY §9.
2. Fix what breaks; record everything in `docs/GOVERNANCE-LOG.md`.
3. Public launch only after: entity + DPA exist, durability test passed,
   one off-site backup taken, `/trust` numbers reviewed by a second person.

## 9. Rollback

Render keeps previous deploys: Dashboard → service → Deploys → select the
last green deploy → **Rollback**. Because state lives on the persistent
disk, a rollback of code does not roll back data — data written by newer
code stays; restore from the pre-deploy off-site backup if schema changes
demand it (document schema changes in the governance log from now on).

## 10. Appendix — CI activation (GitHub Actions)

The workflow is versioned at **`ops/ci.yml`** (Node 20 + 22, syntax checks,
164-assertion smoke suite). It deliberately lives outside `.github/workflows/`
because the automation used to author this repository has no GitHub
`workflows` permission — GitHub rejects pushes that create workflow files
from such credentials. To activate:

```bash
cp ops/ci.yml .github/workflows/ci.yml
git add .github/workflows/ci.yml
git commit -m "ci: activate workflow (ops/ci.yml -> .github/workflows/ci.yml)"
git push origin arena/01a076dc-agrisphere   # needs workflows permission,
                                            # or push from a normal account /
                                            # the GitHub web UI
```

Alternatively create the file in the GitHub web UI (repo → Add file →
`.github/workflows/ci.yml`, paste the content of `ops/ci.yml`). Once active,
every push and PR runs the suite; a red run blocks merges by convention
(no branch protection is configured — enable it in Settings → Branches:
require the CI check on `main`).
